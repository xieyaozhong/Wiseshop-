01 / WHY

小店不是沒有資料，
是資料散在每個地方。

對沒有資訊人員的小店來說，真正的問題通常不是「缺一套大型 ERP」，而是每天花太多時間在重複整理。

01

訂單散落

LINE、IG、電話與現場訂單分開記，容易漏單，也難以追蹤。

→ 集中管理
02

補貨靠記憶

商品賣完才發現，老闆只能靠經驗判斷何時進貨。

→ 預測補貨
03

顧客沒有累積

知道很多熟客，卻沒有消費紀錄與回訪節點。

→ 自動 CRM
04

每天都要重算

營收、支出、待辦、缺貨與回訪，全都由人重新整理。

→ AI 摘要

04 / ARCHITECTURE

新技術可以很先進，
但店家體驗必須很簡單。

第一階段選擇最能降低使用門檻與驗證成本的技術；需要私密金鑰與多人同步的能力，則保留在安全後端層。

NOWPWA + Service Worker

免上架 App Store，手機可直接使用與離線啟動。

NOWIndexedDB local-first

訂單、庫存、顧客與收支先存在店家裝置。

NOWPredictive inventory

用透明規則建立第一版補貨預測。

NEXTSupabase + RLS + Realtime

多人、多裝置、店家資料隔離與即時同步。

NEXTOpenAI Agent / MCP

讓 AI 讀取營運資料並在人工確認後執行動作。

NEXTLINE + n8n

把會員、訂單、通知與工作流串成一條自動化流程。

05 / FIELD VALIDATION

不只展示功能，還要證明店家真的少做了多少事。

場域測試會把「好不好用」變成可比較的數字，作為創業歸故里與後續產品迭代的證據。

01每日整理訂單↓ 50%

目標從 30–60 分鐘的人工作業，縮短到集中操作。

02缺貨發現時間提前 2–5 天

由「賣完才知道」變成依銷量與交期提前預警。

03VIP 回訪名單< 1 分鐘

不再人工翻 LINE 或憑記憶找熟客。

04每日營運摘要自動產生

營收、待單、缺貨與下一步集中在同一畫面。

場域策略

先以 1–3 家臺中地方商家進行 2–4 週真實使用，再依實際痛點決定下一輪功能，不讓店家替新技術測 bug。
