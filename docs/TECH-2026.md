# WiseShop 技術導入策略（2026-09）

目標不是追逐流行名詞，而是把「小店真的用得起、用得懂、網路不好也能跑」放在第一順位。

## 1. 已導入：PWA + Service Worker

用途：讓店家把系統加到手機主畫面，像 App 一樣開啟，並保留離線殼層。

- 對場域驗證最實用：不需要 App Store 上架
- GitHub Pages 本身是 HTTPS，適合 PWA
- 官方參考：MDN Progressive Web Apps
  https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/

## 2. 已導入：IndexedDB local-first

用途：訂單、庫存、顧客、收支先存店家裝置。

理由：IndexedDB 適合大量結構化瀏覽器資料，比 localStorage 更適合營運資料。正式版再同步雲端，避免現場網路中斷就不能工作。

官方參考：
https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API

## 3. 已導入：Predictive Inventory Rules

第一版不需要訓練 ML 模型，直接用可解釋規則：

`平均日銷量 × (供應交期 + 目標覆蓋天數) × 安全係數 - 現有庫存`

這對小店比黑箱 AI 更容易驗證，也能直接量化「提前幾天發現缺貨」。未來資料量足夠後，再升級時間序列模型。

## 4. 已導入：Barcode Detection progressive enhancement

BarcodeDetector 是新型 Web API，但目前不是所有主流瀏覽器都完整支援，因此只做「支援就啟用，不支援就退回 SKU 手動流程」。

官方參考：
https://developer.mozilla.org/en-US/docs/Web/API/BarcodeDetector

## 5. 已導入架構：Supabase Postgres + RLS + Realtime + Edge Functions

repo 已加入 `supabase/schema.sql` 與 Edge Function 範本。

正式版用途：

- Postgres：多店家營運資料
- RLS：以 shop_id 做租戶隔離
- Realtime：店長手機、店員平板即時同步
- Edge Functions：放 LINE / OpenAI / 金流等不能出現在前端的私密金鑰

官方參考：
https://supabase.com/docs/guides/realtime
https://supabase.com/docs/guides/functions

## 6. 已加入後端範本：OpenAI Responses API / Agent 架構

`supabase/functions/ai-copilot/` 已加入安全代理層。

2026 OpenAI API 平台把 Responses API、Agents SDK、Realtime API 與 MCP 作為建立 Agent workflow 的核心能力。WiseShop 的正式 Agent 不應直接拿到「無限制操作店家資料」的權限，設計上採：

1. AI 先讀取最小必要營運摘要
2. AI 產生建議
3. 付款、發訊息、改庫存、刪除等操作要求人工確認
4. 後端記錄操作事件

官方參考：
https://openai.com/api/
https://openai.com/index/the-next-evolution-of-the-agents-sdk/

## 7. 已加入後端範本：LINE Messaging API

`supabase/functions/line-webhook/` 會先驗證 `x-line-signature`，驗證成功後才處理事件。這是 2026 LINE 官方仍特別強調的安全要求。

可用場景：

- 顧客加入好友 → 建立 CRM 記錄
- 顧客傳訂單關鍵字 → 建立待確認訂單
- 店家低庫存 → LINE 通知店長
- VIP 超過 N 天未回訪 → 產生「待人工確認」訊息草稿

官方參考：
https://developers.line.biz/en/reference/messaging-api/

## 8. 已預留：n8n AI / workflow automation

LINE webhook 範本支援把「已驗證事件」送到 `N8N_WEBHOOK_URL`。n8n 適合跨 LINE、Email、Google Sheets、CRM 等服務的流程編排，也能保留 human-in-the-loop。

官方參考：
https://n8n.io/ai-agents/

## 9. 可選、暫不強制：Transformers.js + WebGPU Edge AI

Transformers.js 可在瀏覽器執行模型，並用 WebGPU 加速。這很適合未來做：

- 商品／留言文字分類
- 本機 embeddings
- 簡單影像分類
- 語音辨識的低成本實驗

但 WebGPU 與裝置效能差異仍存在，因此現在不把它設為核心依賴。場域版要保持「舊手機也能用」。

官方參考：
https://huggingface.co/docs/transformers.js/en/guides/webgpu

## 導入優先順序

### Phase A｜現在（場域 MVP）
PWA、IndexedDB、訂單、庫存、CRM、收支、本機 AI 店長、自動化規則、場域 KPI。

### Phase B｜找到 1–3 家合作店家後
Supabase Auth/RLS、Realtime 同步、資料備份、真正登入與多店員權限。

### Phase C｜有真實流程後
LINE webhook、n8n、自動產生回訪／訂單／補貨工作流。

### Phase D｜有補助或穩定收入後
OpenAI Agent、MCP 工具、語音介面、WebGPU Edge AI、進階需求預測。

這個順序的重點是：**新技術服務店家，不讓店家替新技術測 bug。**
